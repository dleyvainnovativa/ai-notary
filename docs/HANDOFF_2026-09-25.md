# NotarIA — Handoff (2026-09-25)

Roadmap of 6 phases implemented in one session. This file is the entry point for the next session.

## 1. Install / deploy

```bash
composer require dompdf/dompdf        # PDF preview (pure PHP, works on Hostinger)
php artisan migrate                   # 2 new migrations (review drafts, parent_document_id)
npm run build                         # review.js / upload.js / theme.css changed
php artisan queue:restart             # ProcessDocumentJob changed (restart queue:listen locally)
```

Nothing else in config/.env. dompdf temp/font cache → `storage/app/dompdf` (auto-created).

## 3. Module extension points (new)

`module.json`
- `"references": {"deed_date": ["escritura.operaciones.*.fecha_operacion"], "address_keys": ["domicilio"]}` — ReferenceResolver
- `"append": {"array": "operaciones", "input": "escritura", "enabled_when": {"operaciones_acumuladas": "1"}, "label": "…"}` — phase 5
- `"importer_class": "Modules\\…\\Importer"` — phase 6 (file `Importer.php`, implements `App\Modules\ImporterContract`)

`formSchema` field hints
- `'derive' => ['rule' => 'birthdate_from_id', 'curp' => 'curp', 'rfc' => 'rfc']` / `['rule' => 'date_from_rfc_moral', 'rfc' => 'rfc']`
- `'money' => true` (PDF: `$1,234.56`, totals) · `'item_label' => 'Adquirente'` (PDF card titles)
- `cp_target` colonias now start as text inputs automatically (no schema change needed)

Extraction schema: `copiado_de` inside `domicilio` (UIF) — removed by the resolver before the form/exporter.

## 5. Open items / decisions pending

1. **Multi-operation UIF TXT not verified against a SAT-accepted file.** GUIDs are now unique and correctly linked (single-op output byte-identical to the verified exporter), but SAT's exact expectation for 2+ operations is unknown. Also: `Configuracion` year/date and aviso date come from the **first** operation — maybe should be the latest.
2. **Fideicomiso (tipo_persona 3) is not exported** (930009/930014 always empty; the persona is skipped). Before phase 6 it was silently emitted as a física line.
3. **UIF persona moral fix changes output** for data where a moral was stored as `tipo_persona = '1'` + 12-char RFC (now emitted as física, following the form). New extractions use `'2'`.
4. **Representante legal** of personas morales and domicilio **correo/teléfono/país/estado/ciudad** exist in the TXT/exporter but not in the UIF form → preserved by import, lost if the form re-saves the persona. Import warns about it.
5. **DeclaraNOT exporter** (unchanged, needs a real file to decide): `Configuracion` hard-codes `001|035|24` (ignores the notario profile); `fecha_nacimiento` emitted as `YYYY-MM-DD` while other dates are `dd/mm/YYYY`; `otro` (other bank) is never exported (only `otro_pago`).
6. **Retention of abandoned drafts** (status "Por revisar" forever) — undecided; suggestion: purge AI output + draft after N days without changes in `documents:cleanup`.
7. Pre-existing: server-side validation is not enforced (`'valid' => true`, `isValid()` commented in export).
8. TXT persona order: físicas (930006) always precede morales (930007), so an imported document lists them in that order.
